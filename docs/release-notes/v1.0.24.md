# v1.0.24

## 修复

- **自动锁定在切后台后偶发失效**：此前只依赖定时器判定锁定，应用进入后台后系统可能冻结进程（缓存应用冻结 / Doze），定时器不会按点触发；回到前台时，已经过期的定时器回调与 `resumed` 生命周期事件会竞争，一旦 `resumed` 先到，定时器就被取消，于是超过「超时时间」回到应用仍然是解锁状态。
  - 现在以「离开前台的时刻」为准判定：回到前台时若离开时长已达到档位就直接锁定；定时器只负责在后台停留期间尽早锁定。
  - 超时前返回应用的体验不变，仍无需重复验证。
- **补发的生命周期事件不再推迟锁定**：框架在 `paused` 与 `resumed` 之间会补发 `hidden`/`inactive`，此前每次收到后台事件都会重新起计时，导致超时判定被不断往后推。现在一次离开前台只记录第一个时刻并只起一次计时。
- **生物识别弹窗期间离开应用不再漏锁**：指纹弹窗会让宿主 Activity 短暂进入后台，这类事件本就不该触发锁定（否则验证成功后会被立刻再次锁定）；但如果用户正好在弹窗显示时离开了应用，此前这次后台会被完全丢弃、之后回到应用也不会锁。现在会先记录下来，弹窗结束且应用确实仍在后台时补上计时。

## 安全与数据

- 不涉及加密方案、密钥派生、数据库结构、备份格式或权限申请，仅调整锁定判定时机。
- 剪贴板清理改为尽力而为（平台通道不可用或系统拒绝时不再抛出未处理异常），且只在真正离开前台的那一次事件执行，不再清除其它应用写入的内容。
- 应用在后台仍会按原策略锁定：锁定时密钥从内存中解除、加密数据库关闭，回到应用必须重新验证。

## 测试

- 新增 `test/features/auth/auto_lock_controller_test.dart`（9 项）：超时前返回不锁定、定时器被冻结时按离开时长补锁定、恰好达到档位即锁定、后台停留超时后由定时器锁定且不重复锁定、「立即」档位直接锁定、未离开前台不会锁定、补发事件不推迟判定、`dispose` 丢弃未完成的计时。
- 新增 `test/features/auth/auto_lock_lifecycle_test.dart`（4 项）：走真实 `flutter/lifecycle` 通道驱动 `KabaoApp`，验证超时后回到前台出现「卡包已锁定」、超时前返回不锁定，以及生物识别弹窗的两条路径。
- 已通过 `dart format --set-exit-if-changed .`、`flutter analyze` 与 `flutter test`（195 项）。
- 真机建议手工确认：设置 → 超时时间设为 15 秒 → 切后台或锁屏 1 分钟后返回，应出现「卡包已锁定」；15 秒内返回则直接回到原界面。

## 已知限制

- 下拉通知栏、系统对话框、分屏等「失去窗口焦点但仍可见」的场景不触发锁定：设置项文案承诺的是「切换后台」后锁定，保持原语义未改动。
- 仍未启用后台隐私遮罩（多任务缩略图会显示离开前的界面），与 `FLAG_SECURE` 一并留待后续处理。
